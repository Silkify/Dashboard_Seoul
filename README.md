# :triangular_flag_on_post: 서울 실시간 도시데이터 파이프라인 & 대시보드

> **과거 데이터를 제공하지 않는 서울시 실시간 API를 30분마다 직접 수집해 시계열 데이터를 만들고,
> 품질 검사와 대시보드를 거쳐 "언제, 어디에, 누가 모이는가"라는 질문에 답하는 프로젝트입니다.**

---

## :fire: 왜 이 프로젝트인가
서울 열린데이터광장의 실시간 도시데이터 API는 **"지금 이 순간"의 인구·혼잡도만** 알려주고, 지난 기록은 주지 않습니다.
그래서 데이터를 **직접 쌓지 않으면 분석할 수 없습니다.**
이 프로젝트는 수집 파이프라인을 만드는 것부터 시작해, 쌓은 데이터로 실제로 쓸 수 있는 인사이트를 끌어내는 데까지 갑니다.

---

## :pushpin: 전체 흐름

```text
 ① 수집          ② 보관           ③ 품질검사          ④ 대시보드          ⑤ 활용
[서울시 API] ──> [저장소] ──> [중복·결측·이상값] ──> [지도·추이·비교] ──> [인사이트]
 30분마다          ______         검사 후 정제            ______          상권·관광·운영
 121곳            (기입)                                (기입)
```

## ① 데이터 수집

| 항목 | 내용 |
|---|---|
| API | 서울 열린데이터광장 실시간 도시데이터 (`citydata_ppltn`) |
| 대상 | 121곳 (고궁·문화유산 / 공원 / 관광특구 / 발달상권 / 인구밀집지역) |
| 주기 | 30분 |
| 실행 환경 | Oracle Cloud VM (24시간 자동 실행) |
| 수집 기간 | 2026-11-__ ~ 진행 중 |

**주요 필드**: 혼잡도(여유·보통·약간 붐빔·붐빔), 인구 최소·최대, 성별·연령대 비율, 거주·비거주 비율, 12시간 예측

**설계 포인트**
- `PPLTN_TIME`은 서울시 집계 기준 시각이라 요청 시각과 다릅니다. 그래서 `수집시각`을 따로 기록합니다.
- 한 번의 응답에서 **실제값**(1행)과 **12시간 예측값**(여러 행)을 나눠 저장합니다. 나중에 예측 정확도를 검증하기 위해서입니다.
- 장소 하나가 실패해도 나머지는 계속 수집하고, 실패한 장소를 로그로 남깁니다.
- Colab은 24시간 켜 둘 수 없어서 클라우드 VM으로 옮겼습니다.

## ② 데이터 보관

| 항목 | 내용 |
|---|---|
| 저장 방식 | JSON (API 응답 원본 형태 그대로 저장) |
| 저장 단위 | ______ (예: 수집 회차마다 파일 1개 / 하루에 파일 1개) |
| 백업 | ______ |

- **원본을 그대로 보관**합니다. API 응답을 가공하지 않고 JSON으로 저장해 두기 때문에, 나중에 정제 방식이 바뀌어도 원본에서 다시 만들 수 있습니다.
- 분석할 때는 JSON을 읽어 `history`(실제값)와 `forecast`(예측값) 표로 변환해서 사용합니다.
- 이 API는 안내 페이지에 "서비스 종료" 공지가 떠 있지만 현재는 정상 동작합니다.
  언제 끊길지 모르기 때문에 **지금 쌓는 데이터 자체가 다시 구할 수 없는 자산**이고, 그래서 백업이 중요합니다.

| 검사 항목 | 방법 |
|---|---|
| 중복 | `장소 + PPLTN_TIME` 기준으로 같은 값이 여러 번 수집됐는지 확인 후 제거 |
| 누락 | 30분 간격 중 비어 있는 시간대 확인 (서버 중단, API 오류 등) |

| 수집 성공률 | 회차별 실패 장소 수, 장소별 누적 실패율 |

## ⑤ 그래서 무엇을 할 수 있는가

쌓은 데이터로 아래 질문에 답하고, 그 답이 실제로 어디에 쓰일 수 있는지 정리합니다.
(아래 내용은 **데이터로 확인할 가설**입니다. 결과가 나오면 숫자로 채웁니다.)

### 1. 언제 붐비는가 → 영업·인력 운영
- 장소별 **피크 시간대**와 평일·주말 차이
- 활용: 매장 영업시간, 아르바이트 인력 배치, 행사 시간 결정
- 결과: ______

### 2. 어디가 인기 있는가 → 입지 선정
- 평균 인구가 많은 곳, 혼잡도가 자주 "붐빔"인 곳
- **평균보다 꾸준함**: 늘 붐비는 곳과 특정 시간에만 몰리는 곳 구분
- 활용: 팝업스토어·신규 매장 입지 후보, 옥외광고 위치
- 결과: ______

### 3. 누가 오는가 → 타깃 마케팅
- 장소별 **주 연령대**와 성별 구성
- **비거주 비율**이 높은 곳 = 외부 방문객(관광·쇼핑) 중심 / 낮은 곳 = 생활권 중심
- 활용: 20대가 많은 곳은 트렌드 상품, 생활권 상권은 생활 밀착형 업종 등 업종·상품 타깃팅
- 결과: ______

### 4. 서울시 예측은 믿을 만한가 → 운영 계획
- 12시간 예측 혼잡도와 실제값 비교 (장소별·시간대별 적중률)
- 활용: 예측이 잘 맞는 곳은 예측값을 근거로 미리 인력·안전 대비 가능
- 결과: ______

### 한계
- 수집 기간이 약 한 달이라 계절·연휴 효과는 반영하지 못합니다.
- 인구 값은 범위(최소~최대)로 제공되는 추정치입니다.
- 매출 데이터가 없어서 "사람이 많다"가 "장사가 잘된다"를 뜻하지는 않습니다.
